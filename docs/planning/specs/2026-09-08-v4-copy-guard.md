# Spec · V4 修复回归护栏（语料断言）

> 状态：**计划中（草案）**——小项。实施前置：宿主 TODO V4 立项（可随时插入，随新工具同步落地）。
> 关联：宿主 TODO V4；ROADMAP reverse-skill「语料级回归护栏」候选；microsoft/DebugMCP 的 root-cause 提示文案可吸收（见宿主 TODO DebugMCP 借鉴）。

## 1. 背景与目标

R1-R8 与新工具的关键**文案/行为契约**没有测试保护——改一句提示语、改一个工具行为，可能悄悄退回旧坑（如 step 返回不再提示 debug_wait、Attaching 不再说明"冻结在 Main 前"），CI 不报错、agent 体验却退化。

**V4 能力**：把「提示语 → 期望动作」的关键契约固化为断言测试，防回归。reverse-skill 用 175 个 `(提示语→期望动作)` 基准用例保证路由经验不随改动退化——本项目取其思想，量级不用那么大（针对实际易碎点）。

## 2. 现状
- 已有回归护栏先例：`McpSessionConcurrencyTests`（stdout 零噪声）、DebugMcpToolsTests（真实调试 e2e）——但都是**行为级**，无**文案级**断言。
- 文案单源：`AppText`/`ToolParameterText` 常量类（编译期 const）。

## 3. 设计

### 3.1 断言两类
| 类 | 断言内容 | 例子 |
|---|---|---|
| **文案契约** | 关键返回/提示含期望片段（与常量类同源避免脆断） | step 返回含「debug_wait」；launch 返回含 pid；Attaching 提示含「冻结在 Main 前」；run_to 返回含「临时断点」 |
| **行为契约** | 关键工具行为不退化 | 断点 list 显示绑定状态；异常过滤 skipped 反馈格式 |

### 3.2 落地形态
- 新增宿主测试类（如 `AgentCopyGuardTests`），挂 AppServices collection（串行，与既有测试同规矩）。
- 断言源：直接引用常量类（`AppText.X`/`ToolParameterText.Y` 的 const）做 Contains 断言——**文案改动若不同步更新测试即红**，反向保护"改文案忘了改测试"。
- 对真实调试行为的文案断言（如 step 返回全文）走宿主 e2e 已有路径补断言，避免新增真实进程测试。

### 3.3 与常量纪律的关系
仓库铁律"跨层文案必须常量类单源"——V4 是它的**测试侧兜底**：即使有人绕过常量类直接写字面量，V4 断言（针对渲染结果）仍能抓住。两者互补。

## 4. 待拍板
1. **断言粒度**：只测"含关键片段"（低脆）vs 全文案精确匹配（高脆）。建议**只测关键片段**（正向契约），全匹配易碎。
2. **新增工具是否必带 V4**：新工具（debug_set/debug_object/debug_verify/ui_*）落地时是否**强制**同批补 V4 断言（建议强制，防新工具立即退化）。
3. **范围**：只宿主语料 vs 也覆盖 Engine 中文错误提示（引擎错误文案散落 .Missing/.Message，抽常量成本高——v1 只覆盖宿主渲染层输出）。

## 5. 验证
- 宿主测试全绿；人为改一句关键文案 → 对应断言红（负向验证一次）。
- 难度：**小**。
