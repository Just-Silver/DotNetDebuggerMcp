## 1. 目标与边界

在 `DotNetDebugger.Web` 库实现 **Blazor Server 展示面**（进程合一，与 MCP 控制面共享同一调试会话），Web 页面提供：

- **代码视图**（Monaco，read-only）：展示被调试进程某模块的反编译源码，叠加断点标记与当前执行行高亮，支持滚动定位到当前停点。
- **状态/面板**：会话状态、调用栈、局部变量、线程。
- **最小人工控制**：continue / step（into/over/out）按钮——控制面以 MCP agent 为主，Web 按钮供人工补位。
- **双模式运行**：随宿主 `--web` 拉起（见 §2）。

**非目标**（沿用总览 spec §1 + vision）：源码编辑、表达式求值、选区内联编辑；不做大前端 IDE。**事件日志 / agent 轨迹时间线回放（§7 数据形状定稿）列 P4.2**，P4 v1 只保证 AgentActionLog 持续记录（P3 已建），不在 v1 页面渲染。

**v1 不做**（沿 P3 遗留 + P2 标注，均属 v2）：pending 断点延迟绑定、PauseAsync（Engine 无此能力，Web pause 按钮 v1 置灰并提示）、多会话并行、PDB 行断点、表达式求值。

## 2. 运行形态：宿主双模式（`--web`）

宿主 `DotNetDebuggerMcp`（dotnet tool）加 `--web [port]` 选项（缺省端口如 8090，具体默认值实施定）：

- **模式 A（MCP + Web 同进程）**：进程以 stdio MCP 长驻为常态，`--web` 让同一进程额外起 Kestrel 监听 HTTP。MCP agent 会话（`debug_*` 工具）驱动调试时，浏览器打开页面实时看到代码视图停点高亮、栈/变量随断点刷新。
- **模式 B（纯 Web 独立）**：无 MCP stdio 会话（非 MCP 启动），页面顶部提供 launch/attach 表单，人工启动/附加目标进程后用同一套面板手动调试。
- 两种模式复用同一 Web 页面与 Session 接线；差异仅在「会话由谁发起」（agent 经 MCP / 人工经表单）。

**约束**：
- **stdout 纪律不破**：Web/Kestrel/ASP.NET 日志禁止写 stdout（MCP 模式 stdout 只走协议）。WebHost 日志通道在实施期配置为 stderr 或文件/关默认 Console。
- 进程生命周期：MCP 模式 Web 随宿主进程共存亡（互不阻塞对方收发）；纯 Web 模式进程为 Web 而活。
- 安全：仅监听 `127.0.0.1`（本机工具，非公网服务）。

## 3. 分层与依赖

```
McpHost(exe) ──> DotNetDebugger.Web ──> Session + Decompiler（只许向下）
宿主装配根：注入 Session 共享实例给 Web（宿主 Services.DebugSessionService.Manager）
```

- Web 库 csproj 从空壳改 Blazor Server 类库形态（`Microsoft.NET.Sdk.Web` 或 `FrameworkReference Microsoft.AspNetCore.App` + Razor SDK），引 Session + Decompiler。精确配置实施计划定。

## 4. 页面布局与面板（v1 核心面）

单页布局（左代码 / 右面板），Blazor Server 组件化：

| 区域 | 面板/组件 | v1/P4.2 |
|---|---|---|
| 左主区 | **代码视图**（Monaco 互操作）：模块/类型选择器 + 反编译源码 + 断点/当前行装饰 | v1 |
| 右上 | **会话状态卡**：当前会话目标、状态（Running/Stopped/Exited）、最近停点（断点 id/异常/位置） | v1 |
| 右中 | **调用栈**：停点线程的栈帧列表（模块!token+offset + 方法名），点击帧切换变量视图与代码定位（v1 至少当前帧） | v1 |
| 右中下 | **局部变量**：当前停点线程栈顶帧的 locals/arguments（标量值展示） | v1 |
| 右下 | **线程**：托管线程列表 | v1 |
| 控制条 | **最小控制**：continue / step into/over/out 按钮 + 「跟随 agent」开关（MCP 驱动时自动刷新，默认开）；pause 置灰（v2 标注） | v1 |
| （P4.2） | **调试事件日志**（滚动 DebugEvent 列表） | P4.2 |
| （P4.2） | **agent 决策轨迹时间线**（AgentActionLog 只读播放器） | P4.2 |

**刷新机制**：v1 用 SignalR 电路内推送（Session 事件 → Blazor 组件刷新）；会话状态/栈/变量从 Session 快照读取（SessionEventBuffer 已维护 CurrentState/LastStop/StoppedThreadId），断点命中事件触发各面板重读。

## 5. 数据流：Web 订阅 DebugEvent

事件源链路（沿用总览 §5）：Engine 写 DebugEvent Channel → Session 消费维护快照 → Web 消费同一事件源刷新 UI。

- Web 读取 `ActiveDebugSession` 状态快照：`SessionEventBuffer.CurrentState / LastStop / StoppedThreadId`（线程安全，P3 已建）。
- Web 需要「事件驱动刷新」时订阅 `session.Events`（`IAsyncEnumerable<DebugEvent>`）或经 Session 加订阅转发——精确机制（谁持有消费循环、Blazor 组件如何订阅生命周期）实施计划定。
- v1 最小可用：**轮询 Buffer 快照**（定时器/事件触发）即可支撑「状态卡 + 栈/变量在断点后刷新」，事件日志 P4.2 才需要完整事件流订阅。实施计划选型：轮询快照（简单够用）优先，事件推送（SignalR）作为增强。

## 6. 文档模型与 IL→行映射（DocumentService）

> **重要修正（2026-09-05 实测确证）**：原设计沿用 research/04 的「SequencePointBuilder 产出 IL→行映射」思路，前提是**有 PDB**。实测证明**无 PDB 程序集该机制不可用**：反编译出的 SyntaxTree 节点 `StartLocation` 全为 (0,0)（探针实测 BigClass 全部方法），`CreateSequencePoints` 的 StartLine 来自节点位置故全错；且无 PDB 时反编译器重写的 ILFunction 无原始 IL offset（ILRange 全 0-0）。**引擎调试器给的停点是「方法 token + 原始 IL offset」（真实字节码），无法映射到无 PDB 反编译文本的具体语句行**。dnSpy 对无 PDB 程序集同样只做**方法级**定位（断点在方法上、执行到方法高亮方法首行）。v1 采用与 dnSpy 一致的方法级方案。

**用途**：代码视图展示反编译源码，停点（模块+methodToken）→ **方法级**定位（高亮该方法的声明/首行），不假装精确到语句行。

**DocumentService 职责**（P3 未独立实现、明确列 P4）：
- `docId`（如 `模块名/类型全名`）→ 反编译文本 + 行列表 + **方法位置表**。
- **方法位置表**（v1 现实映射）：反编译文本中每个方法的 `methodToken → (声明起始行, 方法体结束行)`。来源（实现期选一，先实测再定）：
  1. **文本结构定位**：反编译文本按方法签名行解析——方法声明行特征（`public/private/internal` + 返回类型 + 名字 + `(`）可正则/扫描定位到方法名所在行；结合花括号配平求方法体范围。不依赖 AST 位置（AST 无位置），纯文本层可靠。
  2. **AST 顺序辅助**：遍历 SyntaxTree 的 MethodDeclaration（顺序 = 文本输出顺序），但节点无位置——需结合输出流计数（CSharpOutputVisitor 逐节点写，可包一层计行 TokenWriter 拿每节点起始行）。比纯正则稳，但要自建计行 writer。
  - 推荐 v1：**方案 1 纯文本解析**（方法名 token 已知，从文本找 `名字(` 所在行，前溯签名起始行；方法体范围用括号配平或到下一个同缩进签名）。简单、无 PDB 也稳，够方法级高亮。实现时对 TestSamples 多方法验证命中率，必要时方案 2 兜底。
- **停点定位**：断点命中（模块+methodToken+IL offset）→ 查方法位置表得该 token 方法范围 → 高亮方法声明行；IL offset 因无原始映射**不用于行定位**（仅显示）。
- **反向（设断点）**：Web 点击某方法行 → 用该行所在方法的 methodToken 设**方法级断点**（ilOffset 0，P2 引擎断点即方法入口）。
- **降级策略**（实测依据下的 v1 现实）：无 PDB = 方法级映射是天花板，不存在「映射不到时的高亮假行」问题（v1 不做语句级）；若某方法文本解析不到（极端格式），该 token 不映射，UI 仅状态卡显示位置文本不假高亮。**PDB 语句级映射列 v2**（目标程序带 PDB 时再用 CreateSequencePoints 精确映射，spec §6 原方案作 v2 依据保留）。
- 文本形态注意：现有反编译输出带行号前缀/头部块（宿主 OutputFormatter 约定），**DocumentService 必须产出干净文本 + 独立行号坐标**，不复用 stdout 带行号形态。

**代码视图来源**（用户拍板：泛化模块浏览）：
- 会话建立后从进程已加载模块列表选模块（v1 列表来自 attach 时枚举 + 停点后增量）；类型经 Decompiler 库的元数据组件列；选中类型反编译为文档，映射表随之建立。
- 后续断点命中帧落在该模块时按方法位置表高亮该方法的声明行（方法级，无 PDB 天花板）；跨模块/映射缺失时状态卡显示位置文本（`模块!0xtoken+0xIL`）不假高亮。

> 宿主侧（§9.1）已由「宿主双模式进程形态」调研定稿；Web 库侧（§9.2 BootstrapBlazor/Monaco）待另一调研返回后回填。回填后冻结本 spec。

### 9.1 宿主侧（已定稿，来源：宿主双模式进程形态调研 2026-09-05）

- **宿主 csproj 改造**：宿主 `DotNetDebuggerMcp.csproj` 是 `Microsoft.NET.Sdk` dotnet tool，跑 Kestrel 需加 `<FrameworkReference Include="Microsoft.AspNetCore.App" />`（框架引用，不随 PackAsTool 携带版本问题）；保持 `Microsoft.NET.Sdk` 不改 Web SDK。补 ProjectReference Web 库。
- **`--web` 选项**：加在 `DotNetDebuggerMcpCmd.cs` 参数区（175-200 行一带 `-c`/`-dbg` 旁），`--web-port <port>`（缺省 8090）或 `--web` NoValue + 独立 port，实施定。插入点在 OnExecuteAsync CLI 分支（约 327 行）之后、MCP 装配（约 338 行）之前。`--web` 不是业务参数，不误入 `DispatchCliAsync`。
- **模式 A/B 判别（用户已拍板双模式）**：`--web` 让进程以 MCP stdio 常驻为常态同时起 Kestrel（模式 A）；无 MCP 会话（纯终端非 MCP 启动跑 `--web`）时页面自 launch/attach（模式 B）。判别即「MCP 会话是否在场」——同一 `--web`，宿主默认走 MCP 常驻 + Web；两种模式差异仅在会话由谁发起（agent 经 MCP / 人工经表单）。具体实现：`--web` 分支装配 Web host 并行于 MCP host（若无 MCP 业务参数则 MCP host 仍起但无会话，页面走人工发起）。
- **两套 host 生命周期**：MCP host（`OnExecuteAsync` 约 364 行 `await builder.Build().RunAsync()`）与 Web host（`WebApplication`）是两套独立 service provider；Web host 需与 MCP host **共享同一 CancellationToken 联动**（任一侧停 → 整体退）。共享状态走宿主静态单例（`AppServices`/`DebugSessionService.Manager` 模式），跨 host 天然共享，不依赖 DI 注入。
- **Web 库组件程序集注册**：组件不在启动程序集，宿主装配 Web host 时需 `AddRazorComponents().AddAdditionalAssemblies(typeof(DotNetDebugger.Web 程序集).Assembly)`。
- **Session 注入（依赖方向 McpHost → Web → Session）**：Web 库定义接收入口 `WebHostBootstrap.Configure(DebugSessionManager manager)` 静态方法，把外部传入 manager 存 Web 库内部静态/DI 单例；Web 只用 Session 库 public 类型（`using DotNetDebugger.Session`）**不反引宿主**。宿主装配时调 `WebHostBootstrap.Configure(DebugSessionService.Manager)`。Manager 是 `IAsyncDisposable`——进程退出时（MCP host 停 / CLI return）Dispose 一次，放 Web host `ApplicationStopping` 或宿主收尾，实施定。
- **Web host 日志纪律（关键，防污染 MCP stdout）**：`WebApplication.CreateBuilder` 默认注册 Console provider 写 **stdout**，会撕坏 MCP 协议帧（历史血泪教训）。Web host **不继承** MCP builder 的 `ClearProviders`+`AddConsole(LogToStandardErrorThreshold)` 配置，必须**显式重配**：`builder.Logging.ClearProviders()` + `AddConsole(o => o.LogToStandardErrorThreshold = LogLevel.Trace)`（与 MCP host 同款）或关默认 Console 改 stderr/文件。纯 Web 模式（无 MCP）也建议统一走 stderr。回归护栏：MCP 模式 Web 开着跑既有 `McpSessionConcurrencyTests` 确认 stdout 无噪声。
- **stdout 纪律**：Web/Kestrel/ASP.NET 日志禁止写 stdout；沿用启动/装配异常兜底（Program.cs catch → stderr 中文提示 + 非零退出码）。

### 9.2 Web 库侧（已定稿，来源：BB+Monaco 集成调研 2026-09-05）

- **BootstrapBlazor 10.10.0**（net10.0 首等 TFM，Apache-2.0；10.x 每 1–2 周一发，实施期跟随最新稳定）。Server 装配：`builder.Services.AddBootstrapBlazorServerService()`（官方 demo 用法；实施第一步先确认该扩展所在程序集与签名，退路 `AddBootstrapBlazor()` 官方 README 保证可用）+ `app.UseBootstrapBlazor()` + `MapRazorComponents<App>().AddInteractiveServerRenderMode()`。类库 `_Imports.razor` 加 `@using BootstrapBlazor.Components`；`BootstrapBlazorRoot` 根组件。
- **Monaco：自研 Blazor JS 互操作 + 静态托管 monaco-editor 0.55.1 min AMD 资产**（首选；BlazorMonaco 3.5.0 作参照/备选，二者 MIT，**不要同时引**——两套 monaco 全局冲突）。理由：装饰仅需 5 个实例方法，自研桥 30–60 行；`wwwroot` 静态托管（`_content/`）体积可控（精简子集约 0.5–1.5MB vs BlazorMonaco 全量 15.7MB）；0.56.0 ESM 重构与 AMD 弃用期与「无构建链静态托管」相悖。资产获取：`npm pack monaco-editor@0.55.1` 取 `min/vs/` 子目录静态复制进 Web 库 `wwwroot/`（无 Node 构建链）；必需文件 `loader.js`/`editor/editor.main.js(+css)`/`basic-languages/monaco.contribution.js`/`csharp-*.js`（Monarch，id `csharp`，内置 C# 高亮）/editor.worker.js + assets 实体。注意：0.55.1 editor.main.js 是 Blob-worker 引导，受 CSP `worker-src blob:` 限制——本机 127.0.0.1 无 CSP 预期 OK，加 CSP 头需放行。
- **Monaco 数据流**：服务端组件 → JS 单向为主。Razor `<div id="editor">`，`OnAfterRenderAsync(firstRender)` 里 `IJSRuntime.InvokeVoidAsync("create", id, options)`；**页面/组件须 InteractiveServer 渲染模式**（static SSR 无法初始化 Monaco）。JS→C# 回调用 `[JSInvokable]` + `DotNetObjectReference`（v1 只读视图可不做反向回调）。C#→JS 桥方法：`create/setValue/deltaDecorations/revealLineInCenter/dispose`；`AutomaticLayout: true` 自适配。组件销毁须成对 `Dispose` 编辑器实例 + dotnetObjectReference。
- **装饰规范**：`deltaDecorations(oldIds: [], newDecorations)` 幂等全量重推（无需 C# 维护 old ids）；断点 glyph 圆点（codicon 或自绘 CSS）+ 当前行 `isWholeLine` 背景（顶帧 `#ffff0033` 黄 / 其余 `#7abd7a4d` 绿，research/04 色值）；`revealLineInCenter(lineNumber)` 定位停点。高频 step 下若实测 SignalR 开销大再增量/节流（实施期定）。
- **Web 库 csproj 精确形态**：`<Project Sdk="Microsoft.NET.Sdk.Web">` + net10.0（获 Razor SDK + `_content/` 静态资产透出 + FrameworkReference AspNetCore.App）；项目引用 Session + Decompiler。备选 `Microsoft.NET.Sdk.Razor` + 显式 FrameworkReference。
- **宿主装配形态**（模式 A/B 共用）：`builder.Services.AddRazorComponents().AddInteractiveServerComponents()` + `AddBootstrapBlazorServerService()`；`app.MapRazorComponents<App>().AddInteractiveServerRenderMode()`；Web 库组件程序集不在启动程序集 → `AddAdditionalAssemblies(typeof(Web 程序集).Assembly)`。
- **待实施期实测验证项**（调研标注，写进实施计划 spike）：① `AddBootstrapBlazorServerService()` 签名/程序集（退路 `AddBootstrapBlazor()`）；② 0.55.1 Blob-worker 在本项目 CSP/端口形态可用性；③ dotnet tool 打包含 `_content/` 资产类库时物理布局与 `MapStaticAssets` 兼容；④ `Microsoft.NET.Sdk.Web` 类库被 tool 宿主引用的多余骨架行为；⑤ 高频 step 装饰推送性能阈值。
