# Spec · W2 强制返回 / 跳转执行（SetIP）

> 状态：**计划中（草案）；关键技术已查证，属远期高风险项**。实施前置：宿主 TODO W2 立项 + 用户明确接受风险（破坏性执行控制）。
> 关联：宿主 TODO W2；复用 ILFrame/命令泵停点体系；与 W1（现场改写）互补但风险更高。

## 1. 背景与目标

让 agent **控制执行流向**：跳过出错分支、同一方法内跳到指定行继续、或方法提前"返回"。对标 VS「Set Next Statement」。

现状：只能顺执行（continue/step）或在入口停，不能"跳"——排查"这段代码如果没执行会怎样"要靠改源码重跑。

## 2. 技术查证结论（2026-09-08，本地 ClrDebug 源码实读）

| API | ClrDebug 封装 | 语义 | 风险 |
|---|---|---|---|
| `ICorDebugILFrame.SetIP(nOffset)` | ✅ `CorDebugILFrame.cs:115` | 设置当前 IL 帧指令指针到**同方法内**指定 IL offset | 跳过 finally/catch/状态机/异常处理会**破坏运行时不变式，易崩进程** |
| `CanSetIP(nOffset)` | ✅ `:368` | 预检是否安全（非 S_OK 仍可调 SetIP 但无安全保证——XML 注释明言） | 只是"提示"，不能保证安全 |

**边界**：
- SetIP 是 **IL offset** 粒度（非源码行）——需先有 IL offset（`decompile_il` 工具已能给出方法 IL，P/B 项）。
- **无"方法强制返回"API**——ICorDebug 没有 return 语义跳转；VS 的"Set Next Statement 到外层/返回"实际也受限。
- async 状态机帧（`<X>d__N.MoveNext`）SetIP 行为**未验证**——状态机内部跳转风险更高。

## 3. 方案（若立项，v1 安全子集）

### 3.1 只做"同方法内向前跳转"安全子集
- 宿主 `debug_jump`：参数 `ilOffset`（或反编译视图行→IL 映射）→ 引擎 `CanSetIP` 预检 → 返回安全判定 → **S_OK 才允许 SetIP**，非 S_OK 拒绝并说明原因（防 agent 崩进程）。
- 仅限当前停点线程/帧；仅同方法内（跨方法 = 拒绝）。
- 不做：方法强制返回、跳 finally/catch 块内、async 状态机帧（v1 明确拒绝）。

### 3.2 与 W1 关系
W1 改值 + W2 跳转 = "控制实验"两件套；但 W2 风险显著更高（值写错最多行为错，IP 跳错可能真崩）。**建议 W2 排在 W1 之后且单独评估**。

## 4. 待拍板
1. **v1 做不做**：建议**转远期**（ROADMAP 候选）——风险/收益比低（agent 场景下"跳执行"用断点直达+改值多可替代）；若用户坚持，走安全子集。
2. **UI 形态**：`debug_jump`（同方法内 IL 跳转）还是并入 step 语义。若做，独立工具 + CanSetIP 预检。
3. **async 帧**：明确拒绝还是允许尝试（建议拒绝）。

## 5. 验证（若立项）
- CanSetIP 预检路径单测（S_OK/拒绝两分支）；同方法内跳转 e2e（跳过一段赋值 → 断言变量未被赋）。

## 6. 难度
- **大**（含安全语义设计 + 状态机边界验证）；风险高。建议 ROADMAP，非近期。
