# 实施计划 · W1 现场改写（debug_set SetValue 后继续）

> **For agentic workers:** REQUIRED SUB-SKILL: 用 superpowers:executing-plans 逐 Task 实施（或 subagent-driven-development 逐 Task 派发）。Step 用 `- [ ]` 追踪。

**Goal:** 落地「停点改值再继续」能力：停点用新 MCP 工具 `debug_set <path> <value>` 把局部变量/参数/对象字段/数组元素/引用（置 null 或重定向到同帧对象）改成新值，返回「原值 → 新值」回显，支持 agent 二分定位实验。

**Architecture:** 横跨 Engine（泵内同步写原语）+ Session（value 文本 → DebugWriteValue 文法解析）+ 宿主（新工具 debug_set）。写与读共用 P6 路径解析（`FindRootValue`/字段段/索引段定位到末段值对象），末段按 `DebugWriteValue` 分派写。写必须发生在命令泵内、进程停住态（同线程、无并发），由 Engine 对外 `DebugSession.SetPathValueAsync` 暴露。

**Tech Stack:** C# net10.0、ClrDebug 0.4.2、ICorDebug 值写（`CorDebugGenericValue.SetValue(IntPtr)` / `CorDebugReferenceValue.SetValue(CORDB_ADDRESS)`）、ModelContextProtocol.Server。

**Spec:** `docs/planning/specs/2026-09-08-w1-set-value.md`（2026-09-09 已拍板转正：三层覆盖进 v1 + 引用对象重定向进 v1 + 新值按目标类型转换）。

## Global Constraints（根 AGENTS.md + Engine/Session/宿主 AGENTS.md 铁律）

- 所有 MCP 工具参数带默认值（`string x = ""`，不声明可空）；`[Description]` 中文、面向 agent、注明默认值；每个工具方法带 `CancellationToken cancellationToken = default`；返回 `Task<string>`，一切错误返回中文提示文本，不抛异常。
- 改 MCP 工具必须同 commit 改根 `README.md`（PackageReadmeFile 快照）；新使用者可见变更同批记 `CHANGELOG.md` `[Unreleased]`。
- 日志纪律：stdout 只承载 MCP 协议；调试/自起子进程测试必须排空子进程 stdout/stderr。
- Engine 纯能力层，泵内单线程纪律：新写原语是同步方法在命令泵内执行（经 `PostAsyncResult`），与读同线程，天然无并发；回调线程绝不调 Continue。

```csharp
public Task<DebugWriteResult> SetPathValueAsync(int threadId, string rootName, IReadOnlyList<PathSegment> segments, DebugWriteValue value, CancellationToken ct = default)
```

```csharp
private DebugWriteResult WritePathValue(int threadId, string rootName, IReadOnlyList<PathSegment> segments, DebugWriteValue value)
{
    if (_process is null) throw new InvalidOperationException("无被调试进程。");
    // 线程查找同 ReadPathValue；segments.Count > PathSegment.MaxSegments 同款拒绝
    var thread = FindThread(threadId) ?? throw ...;             // 现 ReadPathValue 内联循环提为私有 FindThread 复用
    var target = ResolvePathValue(thread, rootName, segments);  // 定位到末段（读语义），不转 DebugEvalResult
    var old = ToEvalResult(target);                              // 写前原值回显
    var raw = target switch
    {
        EvalValue.Raw r => r.Value,
        EvalValue.ScalarObj s => throw new InvalidOperationException(
            $"路径 {Describe(rootName, segments)} 末段是引擎合成标量（字符串索引单字符），不可写；请改写到数组元素或字段目标。"),
        _ => throw new InvalidOperationException("不支持的写目标。"),
    };
    WriteTerminal(raw, value, rootName, segments);               // 末段分派（Step 4）
    var after = ResolvePathValue(thread, rootName, segments);     // 写后重读（校验 + 新值回显）
    return new DebugWriteResult(old.Display, ToEvalResult(after).Display, old.TypeName);
}

private static string Describe(string root, IReadOnlyList<PathSegment> segments) => root + string.Concat(segments.Select(s => s switch
    { PathSegment.Field f => "." + f.Name, PathSegment.Index i => $"[{i.Position}]", _ => "" }));
```

- [ ] **Step 4: WriteTerminal 末段分派（按 spike 支持矩阵分支）**

```csharp
private static void WriteTerminal(CorDebugValue target, DebugWriteValue value, string rootName, IReadOnlyList<PathSegment> segments)
{
    switch (target)
    {
        case CorDebugReferenceValue r:                              // 引用目标
            switch (value)
            {
                case DebugWriteValue.Null:
                    r.SetValue(0);                                  // 置 null（CORDB_ADDRESS 0）
                    break;
                case DebugWriteValue.CopyPath p:
                    WriteReferenceRedirect(r, p, rootName, segments);
                    break;
                default:
                    throw new InvalidOperationException(
                        $"目标 {Describe(rootName, segments)} 是引用类型，不能写标量字面量——请置 null 或给同帧对象路径（重定向）。");
            }
            break;
        case CorDebugGenericValue g:                                // 值类型目标（含数组值类型元素 / enum 底层）
            if (value is not DebugWriteValue.Scalar s)
                throw new InvalidOperationException(
                    $"目标 {Describe(rootName, segments)} 是值类型，请给字面量数字/bool（枚举给底层整数值）");
            WriteScalarToGeneric(g, s.Text, Describe(rootName, segments));   // Step 5
            break;
        case CorDebugStringValue:
            throw new InvalidOperationException("字符串内容不可改（构造新字符串需 func-eval，已关）；请置 null 或重定向到已有字符串对象。");
        default:
            throw new InvalidOperationException($"目标类型暂不支持写（{ResolveValueTypeName(target) ?? "<未知>"}）。");
    }
}

private void WriteReferenceRedirect(CorDebugReferenceValue target, DebugWriteValue.CopyPath p, string rootName, IReadOnlyList<PathSegment> segments)
{
    // 源路径在"同一停点、同栈顶帧"解析为引用值，取源引用地址回写（spec 拍板：重定向进 v1）
    var src = ResolvePathValue(_lastThread, p.Root, p.Segments); // _lastThread=解析目标时的同一线程（WritePathValue 内传线程进来更稳——见注）
    if (src is not EvalValue.Raw { Value: CorDebugReferenceValue srcRef } || srcRef.IsNull)
        throw new InvalidOperationException($"重定向源 {p.Root}{...} 不是指向非 null 对象的引用（目标仍在原值，未改动）。");
    // 类型兼容保守校验：两端 ExactType 全名不一致时报错（源/目标同型或赋值兼容才放行）——v1 用全名相等 + target null 不校验
    target.SetValue(srcRef.Value); // srcRef.Value = 被引用对象地址（ClrDebug 属性名以本地源码为准，见注）
}
```

> 实现注（动手前先查再写，禁止臆测）：① `WriteReferenceRedirect` 需要在同一线程解析源路径——把 `WritePathValue` 里的 `thread` 一路传入 `WriteTerminal`/`WriteReferenceRedirect`，不依赖字段；② ClrDebug `CorDebugReferenceValue` 读地址属性名与 `SetValue` 签名以本地 Externals 源码为准（`../../Externals/DebuggerExternals/ClrDebug/ClrDebug/Value/CorDebugReferenceValue.cs`），若属性是 `Address`/`Value` 二选一按实际写；③ 类型兼容校验用 `srcRef` 与目标 deref 的 `ExactType` 全名比较，严格时报 `Incompatible`——拍板倾向严格（v1 宁缺毋滥），可借 `DebugSession` 现有 `ResolveValueTypeName` 能力。

```csharp
private static void WriteScalarToGeneric(CorDebugGenericValue g, string text, string targetDesc)
{
    // 目标标量种类与字节数：按 g.Type（CorDebugValueType）映射；decimal 走 16 字节布局；enum=底层整型（g.Type 已给底层）
    var kind = g.Type; // 查 ClrDebug 枚举成员（Boolean/Char/SByte…/Int32/Int64/Single/Double）——动手前 grep 源码确认成员名
    byte[] bytes = kind switch
    {
        // Boolean: text ∈ {true,false,1,0} → 1 字节
        // Char: 单字符 'x' 或 [0,65535] 整数 → 2 字节 LE
        // SByte/Byte/Int16/UInt16/Int32/UInt32/Int64/UInt64: 十进制（可带 0x 前缀）范围检查 → 定长 LE（BitConverter）
        // Single/Double: InvariantCulture 解析（允许 f/d 后缀）→ 4/8 字节
        // Decimal: decimal.Parse + Decimal.GetBits(decimal)[4] 按 (lo, mid, hi, flags) 排 16 字节 LE
        _ => throw new InvalidOperationException($"目标 {targetDesc} 类型 {ResolveValueTypeName(g) ?? "<未知>"} v1 不支持写。"),
    };
    // 释放原生内存的注意：SetValue 需要 IntPtr——用 stackalloc/fixed 或 GCHandle 短期固定后调用 g.SetValue(ptr)
    // 全部在泵内同步完成，无跨 await；写失败（尺寸不符等）捕获转中文提示
}
```

```csharp
// src/DotNetDebugger.Session/Evaluation/WriteValueParser.cs
using DotNetDebugger.Engine.Models;
namespace DotNetDebugger.Session;

/// <summary>debug_set 新值文本 → DebugWriteValue（W1）。判定不依赖目标类型：
/// null/bool/数字字面量 → Scalar；其余（标识符/成员链/下标）按 ExpressionParser 解析为对象路径 → CopyPath；
/// 字符串字面量产 Scalar（引擎按目标类型决定：值类型字符可写、字符串内容构造拒绝）。失败抛 ExpressionEvaluationException（中文）。</summary>
public static class WriteValueParser
{
    public static DebugWriteValue Parse(string text)
    {
        var t = text.Trim();
        if (t.Length == 0) throw new ExpressionEvaluationException("value 为空。新值支持：null / true|false / 数字（整数/小数/科学计数/可带 m/f/d 后缀或 0x 前缀）/ 同帧对象路径（引用重定向）。");
        if (t == "null") return new DebugWriteValue.Null();
        if (t == "true" || t == "false") return new DebugWriteValue.Scalar(t);
        if (IsNumberLike(t)) return new DebugWriteValue.Scalar(t);
        // 路径重定向：复用 P6 文法，要求解析为路径（字面量已在上方消费）
        if (ExpressionParser.Parse(t) is PathNode p)
            return new DebugWriteValue.CopyPath(p.Root, p.Segments);
        throw new ExpressionEvaluationException(
            $"value「{text}」既非字面量也非对象路径。支持：null / true|false / 数字 / 或同帧另一条对象路径（如 cfg.Backup、alt.Tag、arr[0]）。");
    }

    private static bool IsNumberLike(string t)
    {
        // ^[+-]?(?:0[xX][0-9a-fA-F]+|\d+(?:\.\d*)?|\.\d+)(?:[eE][+-]?\d+)?[mMfFdD]?$
        // 同时排除裸 "."/"-"/"+" 与带字母后缀外的杂串
    }
}
```

```csharp
// 模板对齐 DebugEvaluateTool（McpServerToolType + McpServerTool + Description + TryRequireStopped + 中文错误捕获）
[McpServerTool]
[Description("改写停点现场的值后继续（进程需停在断点/异常）：把局部变量/参数/对象字段/数组元素改成给定值，返回「原值 → 新值」回显。path 为目标路径（根=栈顶帧局部/参数名，支持字段 .a 与数组下标 [n]，同 debug_evaluate）。value 支持：null（引用置空）/ true|false / 数字（整数/小数，按目标类型转换，枚举给底层整数值）/ 或同帧另一条对象路径（引用重定向，如 cfg.Backup）。不支持：改 readonly/const/静态字段、构造新对象、改字符串内容、表达式/方法调用。注意风险：写目标进程内存可能使其崩溃，只改你确认的变量；改完用 debug_continue 观察行为是否变化。")]
public static async Task<string> DebugSet(
    [Description("目标路径（必填），如 scores[2]、b.A、i、cfg.Current（根为栈顶帧局部/参数名）。")] string path,
    [Description("新值（必填）：null / true|false / 数字（可带小数或 m/f/d 后缀）/ 同帧对象路径（引用重定向）。")] string value,
    [Description("线程 id；缺省 0 = 用最近停点线程。")] int threadId = 0,
    CancellationToken cancellationToken = default)
{
    if (string.IsNullOrWhiteSpace(path)) return "缺少 path（必填）。目标路径如 b.A、scores[2]、i。";
    if (string.IsNullOrWhiteSpace(value)) return "缺少 value（必填）。支持 null / true|false / 数字 / 同帧对象路径。";
    if (!DebugInspectTool.TryRequireStopped(out var active, out var error)) return error;
    var tid = threadId > 0 ? threadId : active.Buffer.StoppedThreadId;
    if (tid <= 0) return "无停点线程可写（先 debug_continue 运行至断点停下）。";
    try
    {
        if (ExpressionParser.Parse(path) is not PathNode target)
            return $"path「{path}」不是有效路径（应为变量名/字段/下标链，如 b.A）。";
        var write = WriteValueParser.Parse(value);
        var result = await active.Session.SetPathValueAsync(tid, target.Root, target.Segments, write, cancellationToken);
        DebugSessionService.Manager.Actions.Log("debug_set", $"{path} = {value}", "ok");
        return $"路径 {path} 已改：原值 {result.OldDisplay} → 新值 {result.NewDisplay}" +
               (result.TypeName is null ? "" : $"（{result.TypeName}）") +
               "。进程仍在停点——可用 debug_evaluate 复核；debug_continue 运行观察行为变化。";
    }
    catch (ExpressionEvaluationException ex) { return ex.Message; }     // 文法/求值语义错误
    catch (InvalidOperationException ex) { return ex.Message; }          // 引擎路径写错误（段/类型/readonly/降级提示）
    catch (Exception ex) { return $"改写失败：{ex.Message}"; }
}
```
